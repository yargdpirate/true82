# TRUE 82 art variants: the contract (v67, 2026-09-30)

**The owner's ask (2026-09-30):** the season reel's giant L "gets pretty stale seeing the same L over again" over an
average season's losses. He wants "a ton of different variations on that look and style ... if you saw 10 in a row,
you're getting 10 different of them, and they're all different enough that it doesn't feel boring". The same for the
mountain picture at the end (the results print, THE SHAPE OF A SEASON) and the reel's little win and loss dots. "The
more the better", with one limit: performance on the player's side must be unaffected, even on an iPhone SE.

**The answer to the limit:** the art is code, not pictures (a variant is 1 to 16 KB of drawing instructions), and each
variant is its own file that the phone downloads only when its shuffle bag deals it, in the background during the
draft, cached for a year. A season uses at most 14 loss moments, one dot set and one scene, so the download per season
is the same whether the library holds 30 variants or 1,000 (the list of the library, art-index.js, grows by about 100
bytes a variant). What keeps the SE smooth is a per-variant budget that every variant must pass (below), not the size
of the library.

This file is the contract every variant and both engines build against: the spec. **art/README.md** is the how-to
(adding a variant in five steps, the kit cheat sheet, the harness), art/CRAFT.md the drawing craft, art/CONCEPTS.md the
briefs, art/CONTRACT-FX.md part two (the FX kinds and 82-0). If the code and this file disagree, fix one of them in the
same commit.

## The three kinds

| kind | where | built-in (today's look, the fallback) | how often a player meets one |
|---|---|---|---|
| `loss` | the reel's big moment on a heavy loss (losses 1 to 14 of a season; `heavy()` in reel-riso.js) | `classic`: the giant misregistered L that drains | up to 14 a season, never a repeat until the bag empties |
| `dots` | the reel ledger's win and loss stamps, for a whole season | `classic`: coins, rims, streak rings; loss rings, cracks, splats, drips | one set per season |
| `scene` | the results print (banner on the page, 1080x1350 share poster) | `lake`: mountains over a lake, the record as the ridge | one per season |

## Files

- `art-core.js` (hand-written; `window.T82ART`). index.html loads it `defer`, then art-index.js, before app.js,
  reel-riso.js and results-riso.js (only index.html runs the game). It touches no `document`, sets no timer and reads
  no storage until it is called.
- `art-index.js` (GENERATED by `node tools/art-index.js`; never hand-edit): calls `T82ART.index([...])` with one entry
  per variant file: `{ kind, id, name, file: "art/<kind>/<id>.js?v=<key>", on: true|false }`. `on` = dealt in the
  game; the lab shows every entry. The keys are the cache-key manifest's (tools/cache-keys.json): every art file is in
  the manifest, and art-index.js is one of the pages `tools/cache-keys.js` scans for references, so
  `node tools/cache-keys.js --stamp <key>` keys a changed variant like any other file (and then art-index.js itself;
  the stamp repeats until a pass changes nothing).
- `art/loss/<id>.js`, `art/dots/<id>.js`, `art/scene/<id>.js`: ONE variant per file. The file is an IIFE that calls
  `T82ART.add(kind, id, def)` exactly once and touches no other global. `id` = the file's name, `[a-z0-9-]`. The
  generator reads the files without running them and refuses (writes nothing, exits 1) a file whose id is not its
  name, whose kind is not its folder, that calls add more or less than once, whose def has no plain-string `name`, or
  that takes a built-in's id (`loss/classic`, `dots/classic`, `scene/lake` are reserved). It accepts
  `T82ART.add(...)`, `window.T82ART.add(...)` or a local name for it (`var A = window.T82ART; A.add(...)`), with the
  def an object literal or a `var` set to one in the same file.
- `art/enabled.json`: `{ "about": "...", "off": ["kind/id", ...] }`, the looks the game does NOT deal (the lab still
  shows them). Every other file is on. A name in `off` with no file behind it is an error. After an edit:
  `node tools/art-index.js`.
- The built-ins live inside the engines (`classic` loss and `classic` dots in reel-riso.js, `lake` in results-riso.js)
  and register themselves with `builtin: true` (at load, and again when a reel or print starts if art-core.js arrived
  later). The engines work exactly as before when art-core.js is missing: `T82RISO.create(ov, season)` with no opts
  prints every frame of v66.4 pixel for pixel, and a print spec without `scene` prints the lake pixel for pixel. (One
  deliberate change, v67: at a few grid widths, 263, 308-309, 323-324, 338-339 px and the like, a floating-point slip
  laid a 15-game month out as 14 columns and one; it now prints one row of 15. The owner's 375 px phone, a 307 px
  grid, and 320 px, a 254 px grid, are unchanged.)
- `_headers`: Cloudflare Pages allows at most 100 header rules, so the art files share ONE wildcard rule (`/art/*`:
  the year-long immutable cache), never one rule per file (`tools/cache-keys.js` flags a rule of its own). Everything
  under art/ is cached that way once deployed, docs and PNGs included: keep living pages (labs) outside art/.
- The bench: `docs/art-lab/qa.html` (`window.T82QA`, and `?watch=kind:id` to watch one look live) and
  `tools/art-qa.mjs` (the budgets). See "The QA hooks" and the budgets below.

## T82ART (art-core.js)

```
T82ART.add(kind, id, def)   register a look (variant files and the engines' built-ins). kind: loss | dots | scene;
                            id: [a-z0-9-]+; def: an object. A later add of the same id replaces the earlier one.
                            Returns true, or false (with a console.warn) when kind, id or def is not valid. Resolves
                            a pending load() of that id at once.
T82ART.get(kind, id)        the def, or null (own properties only: an id like "constructor" is safe)
T82ART.index(list)          art-index.js calls it once; keeps the valid entries { kind, id, name, file, on }
                            (on counts only when it is exactly true). Returns how many it kept.
T82ART.catalog(kind)        copies of every index entry of a kind: on or off, loaded or not (the lab lists them)
T82ART.enabled(kind)        the ids a bag deals: the index's "on" entries plus the registered built-ins
T82ART.load(kind, ids)      Promise -> the requested ids that are registered when it settles. ids: an id or an
                            array. For each id that is in the index and not yet registered it injects
                            <script async data-t82-art="kind/id" src=file?v=key> (the file resolved against
                            art-core.js's own URL, so a page in a subfolder finds art/). A file finishes when it
                            registers, loads, errors or times out (LOAD_MS, 8 s); two calls for one file share one
                            request; a file that errored, timed out or never registered is skipped for the rest of
                            the visit. Never rejects. Never loads anything on its own.
T82ART.deal(kind, n)        PEEK the next n ids of this device's shuffle bag (consumes nothing: two deals agree)
T82ART.used(kind, id)       consume: take the first occurrence of id out of the bag and remember it as last-used
T82ART.forced(kind)         QA: the ids ?art= forces on a test build, or null (below)
T82ART.KINDS, .LOAD_MS, .version ("v67")
```

**The bags.** One per kind per device, in localStorage: `t82-art-bag-<kind>` holds `{ k, b }` (`k`: the enabled ids
the bag was drawn from; `b`: a list of cycles, the first one in progress, the rest drawn ahead so a long peek stays
stable) and `t82-art-last-<kind>` the last-used id.
- A cycle is one shuffle (Math.random: a bag is per device and never replayed) of every enabled id, so every look
  plays once before any repeats. A new cycle never starts with the id before it (the previous cycle's last, or the
  last-used one when the bag is empty): no look twice running at a seam.
- On every deal, ids switched off or deleted leave every cycle at once; ids new since the bag was drawn are inserted
  at random into the cycle in progress and the cycles drawn ahead are redrawn (so a growing library shows up next
  season, and a bag drawn when only the built-in existed does not lead every cycle with it).
- Every storage call is wrapped. In private mode, or when a write fails, the bag lives in memory for the visit and
  reads stop trusting the stale stored copy.
- Cost (M1, unthrottled, median): deal 0.06 ms / used 0.007 ms at 30 looks; 0.82 / 0.13 ms at 1,000. The stored bag
  is about 350 bytes at 30 looks, 10 KB at 1,000.

**?art= (QA).** On any host but `true82.net` and `www.true82.net` (case-insensitive), `?art=loss:seal+drip,dots:balls,
scene:skyline` forces those looks. A `+`, a space or `%2B` separates ids; encoded commas and colons work; invalid ids
are dropped; a kind with no valid id is not forced. `forced(kind)` returns the list (app.js repeats a loss list to
fill the season: `loss:seal` makes every heavy loss seal, `loss:a+b` plays a, b, a, b...; dots and scene take the
first id). The live site ignores it.

## The game's flow (app.js)

1. **The deal** (`artDealRun()`, in `newGame()` right after `game_start`): nothing without art-core.js, and nothing
   in Kaman. When the reel will play (`seasonReelPlays()`: a standalone Classic or Presti run, the same condition
   `showResults()` uses) it deals `loss` 14, `dots` 1 and `scene` 1; every other mode (the Daily, Pro, the boards)
   deals only the scene: those modes never show the reel, so their loss files would be pure download. A forced list
   wins over the bag (`artPick`). The deal rides `G.art = { loss, dots, scene }` for the whole run.
2. **The fetch:** 1.4 s after the draft starts (after the first ticket's slot reels land), in requestIdleCallback
   where the browser has it (iPhones do not: at once there), `T82ART.load` for the dealt ids. Nothing is fetched
   before a draft starts, so the home page and the first paint never pay for art. A built-in fetches nothing.
3. **The reel:** `T82RISO.create(ov, season, { loss: G.art.loss.slice(), dots: G.art.dots, onUse })`, where `onUse`
   books `T82ART.used(kind, id)` one tick later (setTimeout 0: the engine calls it inside an animation frame, and a
   phone's storage write must not land there). Without art-core.js (no `G.art`) app.js makes the old two-argument
   call. What the engine does with the list: "A loss moment" and "A dot set" below.
4. **The results print:** `resultsPrintSpec()` adds `scene: id` only when `resultsPrintScene()` returns one: the dealt
   scene if it is registered at the run's first print, settled once a run on `G.art.print` (so a Heat Check reprint
   and the poster keep the same scene); a scene that has not arrived prints the lake and stays in the bag. Without
   art-core.js the spec has no `scene` key at all (byte-identical to v66.4's). `pal` is unchanged (the paintings bag).
   `mountResultsPrint()` calls `T82ART.used("scene", id)` once a run, after the mount succeeds. It fires even when
   the scene then throws and the lake prints instead: a broken look must not sit at the head of the bag every season.
5. **Failure:** a throw inside a variant turns that variant off for the session and its moment, season or print falls
   back to the built-in; it never breaks the reel or the results (the engines wrap every call). One `console.warn`
   per variant: `[t82] art loss:<id> is off for this session: <error>`, `[t82] art dots:<id> is off for this
   session: <error>`, `[t82] art scene:<id> is off for this session (the lake prints instead): <message>`.

## A loss moment

```
T82ART.add("loss", "seal", {
  name: "Rubber Seal",                 // the lab's label (2-3 words, a plain string: the generator reads it)
  by: "A LOSS seal slams at an angle, ink pools, the stamp lifts off.",   // one line for the lab
  prep: function (K) { return [job, job, ...]; },   // optional; see Prep
  hit: function (K, E) { ... },        // optional; once, at the slam. Absent: K.hitClassic(E) (rings, spray, flash,
                                       //   shake). For no hit at all: hit: function () {}
  veil: true,                          // optional; anything but false or a function = the classic veil; false = none;
                                       //   function (K, E, e) = its own
  caption: true,                       // optional; anything but false or a function = the classic caption, its first
                                       //   baseline at (K.box.cx, K.box.y1 + 26) from e >= 0.07; false = none;
                                       //   function (K, E, e, x, y) with that same point (it must still say E.sub, E.sub2)
  draw: function (K, E, e) { ... }     // REQUIRED; every frame of the moment; e = seconds since the slam, 0 .. E.dur
});
```

- **The order of a frame** (on the card's effects canvas, `K.g`): every moment's veil, then the rings, then the
  sparks, then each moment's hero (`draw`) and caption. The engine saves the canvas state around each call and places
  `K.box` before each one.
- **E** (the event): `t0, dur` (seconds the cursor holds: about 0.4 to 2.2; it scales with the season's pace),
  `first` (the season's first loss), `lossNo` (1-14), `lossRun`, `prevStreak`, `x, y` (the wound: the stamp's center
  in card CSS px), `seed` (per game: `((gi + 3) * 7919) >>> 0`; replays match), `sub, sub2` (the caption lines, from
  `lossCopy`), `city`, `date`.
- **K.box**: the open span where the hero lives, sized and placed exactly as the classic L's (above or below the
  wound, never over the row that just lost; below when it has room; the whole card under the head when neither side
  has 150 px): `{ x0, y0, x1, y1, cx, cy, size, span, spanTop }`. `x0..x1` is the card's width; `y0..y1` the L's
  height (`cy - 0.4 size` to its baseline at `cy + 0.36 size`); `size` = the classic L's height (70 px up to 95% of
  the card's width); `spanTop` and `span` the whole open span. `K.w, K.h` are the card's size and `K.top` the head's
  height (the area under it is the moment's). `K.box` is null in prep.
- **K.g** is the card's effects canvas context in card CSS px (the engine set the device-pixel transform). Draw with
  `globalCompositeOperation = K.blend` and halftone fills (`K.pat`) or screened canvases (`K.screen`).
- **K.ready** is true once the theme's display face has loaded (the engine's gate opens about 0.32 s into the reel):
  classic draws no L before then, and a hero set in the display face should wait for it too.
- **The timeline:** the hero reads by `e = 0.25` and is gone by `e = E.dur` (`K.fade(E, e)` gives the classic 0.2 s
  fade-out multiplier). It must read at both ends of the duration range: a 0.45 s moment late in a bad season and a
  1.9 s moment that kills a long streak.
- **Prep:** expensive work (screening a big mass into halftone dots) happens before the moment, in idle time. `prep(K)`
  returns an array of jobs (functions, no arguments) that fill `K.st` (the moment's own state object). The rules:
  - The prep body runs together with the first job, in the same idle step; a job may push more jobs onto the
    returned array. `K.box` is null during prep: print at a fixed size and scale when drawing.
  - The engine keeps a window of at most THREE moments (the next heavy losses whose looks are registered, in play
    order), runs ONE job per idle moment (requestIdleCallback, or 16 ms timeouts where there is none), the window's
    first moment first, and runs any missing job synchronously if a loss arrives first.
  - When the dealt list runs out the rest of the season is classic, but the classic fallback joins the window only
    once it is the very next moment (a dealt season never prints a classic L it will not play). A dealt `"classic"`
    preps in its turn like any look. Classic's eighteen levels are kept for the reel's whole life.
  - Before a variant's first job the engine sets the theme's faces once (mono 700 and 500, display 800 and 700), one
    per idle step, only when a variant is in the window: the page's first canvas text in a face costs up to ~35 ms
    at 4x throttle, and that belongs to no variant.
  - A variant moment's canvases are freed when it ends (every canvas found in `K.st`, its arrays and objects, gets
    width and height 0), and on destroy. Each listed moment is its own unit with its own `K` and `K.st`, even when the
    same id is dealt twice.
- **The list:** each heavy loss takes the next listed id that resolves: `"classic"`, or a registered def with a `draw`
  function that has not been turned off. An id that does not resolve (not loaded yet, unknown, or off) is skipped and
  stays in the bag. **onUse("loss", id)** fires when a listed id's moment starts, even if it then fails and plays as
  classic (so a broken look does not sit at the head of the bag); never for the unlisted classic fallback.
- **Robustness:** every variant call is wrapped. A throw in prep, hit, veil, draw or caption turns the variant off for
  the session (its units are freed; a moment it is playing carries on as classic; a throw mid-frame resets the card's
  canvas, whatever state the variant left on it). A variant that died in prep before its turn is skipped like an unregistered id.
- **Rules:** the loss ink (`"loss"`) dominates; secondary inks from `pop`, `key`, `night`, `light`, `stock`. Never the
  win ink or gold for a loss's hero (gold is a hot streak, aqua is a win). At least four in five variants keep the
  letter L as the anchor (any material, letterform, construction); the rest may say LOSS another unmistakable way
  (the word, a scoreboard, a ball that bricks), and their `by` says so.

## A dot set

```
T82ART.add("dots", "balls", {
  name, by,
  reach: { w: 1.7, l: 3.4 },   // how far (in dot radii R) a stamp's ink reaches from its center while it moves
                               //   (default shown; each clamped to 0.5..6)
  live:  { w: 0.24, l: 1.5 },  // seconds a win / a loss keeps moving after its stamp (default shown; 0..3)
  inks:  { a: "win", b: "pop", c: "loss" },   // optional; the plates' inks, any reel ink (default shown)
  marks: function (K, D) { ... },             // optional; seeded per-game details stored on D, once per stamp (default:
                                              //   classic's drips, splats and cracks for a loss)
  a: function (K, g, D, c, R, e) { ... },     // plate a's tone for one stamp (black alpha = coverage)
  b: function (K, g, D, c, R, e) { ... },     // at least one of a, b, c; a missing plate prints nothing
  c: function (K, g, D, c, R, e) { ... },
  win:  function (K, p, info) { ... },        // optional; the burst at a win's stamp (default: classic)
  lossHit: function (K, p, info) { ... }      // optional; the small hit at a NON-heavy loss (default: classic)
});
```

- Each plate function is called for EVERY stamp of the month (wins and losses, settled ones too) in that plate's
  pass, on every print of the strip, so keep it cheap. `g` is a scratch context in strip CSS px; lay tone (`K.tone`).
  `D`: `{ idx, win, t0, streak, gi, cl, lastRow, pitch }` plus whatever `marks` stored (`lastRow`: the stamp sits in
  the month's last row; `pitch`: the cell size in CSS px; both refreshed on every print). There is no `D.rnd`: seed
  from `D.gi` in `marks` (`K.rand(((D.gi + 1) * 2654435761) >>> 0)`). `c` = the stamp's center `[x, y]` (strip CSS
  px), `R` = the dot radius (`pitch * 0.36`, about 6 to 10 px on a phone), `e` = seconds since the stamp (about 1e6
  when settled).
- `win(K, p, info)` and `lossHit(K, p, info)`: `p` = the stamp's center in card CSS px; `info` = `{ gi, cw, cl,
  streak, prevStreak, lossRun, city, date, pace, seed, dur }` (`dur`: the loss's hold in seconds; 0 for a win). They
  get the reel's kit (`K.ring`, `K.spark`, `K.shake`; `K.flash` never fires outside a heavy loss's hit).
- **The set is chosen once**, at the season's first stamp: `opts.dots` if it resolves (a registered def with at least
  one plate function, not turned off), else classic. **onUse("dots", id)** fires then, once, when the id came from
  opts and resolved (an explicit `"classic"` too).
- **Still before live ends:** a stamp must reach its final pose at least one frame before its live window ends (the
  strip stops redrawing it then, and the settled ledger must match `T82RISO.strip()`'s reprint pixel for pixel; the
  harness checks it). Stay inside `reach`: ink outside it leaves stale dots behind in the live strip.
- **Robustness:** a throw anywhere in a set (marks, a plate, win, lossHit) switches the whole season to classic, the
  stamps already down too (they are re-marked and reprinted at once). `T82RISO.strip({ ..., dots: id })` falls back
  the same way.
- **Rules:** at 6 px a win and a loss must be told apart at a glance by shape AND ink, never by ink alone. Streaks (10,
  20, 30 straight) stay visible. A settled ledger must still read as a print of the season (the owner keeps the drips:
  every loss still reads at the end).

## A scene

```
T82ART.add("scene", "skyline", {
  name, by,
  lights: ["golden", "dusk", "night"],      // optional; the paintings it prints (unknown entries dropped; none = all
                                            //   three). A spec.pal it lacks prints in its first.
  derive: function (K, D, L) { ... },       // optional; add the scene's geometry to D, seeded by D.seed
  layers: function (K, P, D, L) {           // REQUIRED; 1 to 8 layers, each drawn as tone and screened into its ink
    return [ { ink: "light", role: "sky", draw: function (g) { ... } }, ... ];
  },
  body: function (g, D, L) { ... }          // optional; see below
});
```

- **D (the season, from the engine's derive; the scene gets its own copy):** `m[0..82]` (the running margin), `X(g)`,
  `front(x)` (the lake's ridge in scene units), `far1, far2`, `wp, w, l`, `fillX` (the gauge: wins/82 of the way
  across the frame), `losses` (indexes of the lost games), `pal` (golden, dusk or night: `{ key, light, top, band,
  waterB, ridgeB, ridgeP, sr }`), `sx, sy, sr` (the sun), `moon {x, y, r}`, `stars`, `glints`, `ripples`, `strata`,
  `seed`, `peak` (the game index of the best margin), `games` (82 x 0/1, or null when projected), `spec`. `m`, `games`,
  `losses` and `pal` are copies: the engine keeps its own season for the strip, the gauge, the title and the reveal, so
  a scene that changes D can never misprint the record.
- **L (the layout):** BANNER (1000x660 scene units, `vs` .52, `rs` .62) and POSTER (1000x1250, `vs` 1, `rs` 1):
  `VW, VH`, `FX0, FY0, FX1, FY1` (the frame), `WL` (the .500 line), `X0, X1`, `SC` (units per game of margin),
  `vs, rs`, `strip`, `roster`, `stars`, `rip`.
- **P (the plate, read only):** `{ W, H, vw, vh, k, pitch, TH, rgb, ... }`.
- **Layers:** each `{ ink, role, draw(g) }`. `draw(g)` lays tone in scene units; the engine has already saved the
  context, clipped it to the frame and (for land) to the gauge; it restores afterwards. A bad list (not an array, 0 or
  more than 8 layers, an unknown ink or role, no draw) counts as a throw.
- **Roles:** `sky` prints down first at the reveal (n sky layers share the lake's 0.32 s stagger, 0.42 s each); `land`
  fills in from the left up to `D.fillX` (the owner's gauge: color only up to the win rate), clipped to it, from
  0.62 s; `line` is the season's line and its loss marks, printed across with the season and never clipped by the
  gauge.
- **The engine adds:** the registration marks into the FIRST sky layer and the FIRST land layer of each of `light`,
  `pink` and `blue`; the 82-game strip into the first land layer of each of those three (a scene without one gets a
  blank land layer appended); line layers get neither.
- **body(g, D, L):** the region the fill's front line (the gauge's edge) runs down through. Add a path to `g` (the
  engine calls beginPath() before and clip() after). Absent: under `min(D.front(x), L.WL)`, the lake's land and water.
- **Inks:** `light` (the painting's light: `sun` for golden, `orange` for dusk, `teal` for night), `pink`, `blue`,
  `sun`, `orange`, `teal`. They are the reel's inks under their older names: `pink` = the reel's `pop`
  (--t-print-pop), `blue` = `key` (--t-print-key), `sun` = `gold` (--t-print-sun), `orange` = `dusk`
  (--t-print-dusk), `teal` = `night` (--t-print-night, the violet). On dark stock `blue` prints at 55% (a glow).
- **Engine-owned, the same in every scene:** the strip, the registration marks, the title and record, the roster, the
  fill's front line, the reveal's timing, the poster's foot.
- **Robustness:** every scene call is wrapped (derive, layers, each draw, body: dry-run once when the print is
  prepared, then guarded every frame). A throw retires the scene for the visit and that print falls back to the lake;
  a poster whose scene throws mid-bake starts over as the lake.
- **Perfect scenes** (`perfect: true`, art/CONTRACT-FX.md: dealt only for an 82-0) are not wired yet: today's bag and
  app.js would deal one for any season. Add none until that part lands (the harness already prints one as 82-0 only).
- **Rules:** the season's line is the picture's dominant silhouette, readable at 320 px; every loss is marked on it;
  the gauge holds; it works in the BANNER and the POSTER, in all its lights, on dark stock (screen) and light stock
  (multiply). Vector drawing only: no per-pixel loops in a scene (the engine screens).

## The kit (K)

Both engines hand every call a kit. Variants use it and nothing else.

**The reel's kit (loss moments and dot sets):**
- **Inks** (`K.inks` lists them; each on its own screen angle, so two inks over each other make a rosette, not a
  moire): `loss` (--t-loss, 14 deg), `pop` (--t-print-pop, 45), `win` (--t-win, 18), `key` (--t-print-key, 72),
  `gold` (--t-print-sun, 0), `night` (--t-print-night, 63), `dusk` (--t-print-dusk, 34), `light` (--t-light, 56),
  `stock` (--t-print-paper, 76). The loss hero's partners all sit 28 deg or more off the loss ink. A theme without one
  of the new tokens lends an existing ink (key and night borrow pop, gold and light borrow win, dusk borrows loss).
  An unknown ink name throws (and so turns the variant off).
- **Colors:** `K.rgb(ink)` -> `[r, g, b]`; `K.pat(ink, cov, g?)` -> a halftone CanvasPattern of that ink at coverage
  `cov` (0..1, quantised to sixteenths), pinned to the device pixels of `g`'s CURRENT transform (default `K.g`): take
  it right before the fill, after your transforms, and the dots never swim; cached. `K.blend` is the composite for ink
  on the stock ("screen" on dark stock, "multiply" on light). `K.tone(a)` is the coverage mask color (black at alpha
  a): the only black a variant may write.
- **Print (prep only, per-pixel cost):** `K.plate(cssW, cssH, seed)` -> `P` (`{ W, H, k, ... }`, device px);
  `K.screen(P, ink, draw)` -> a canvas of P's size (draw tone in CSS px with `draw(g)`; it is screened into the ink's
  dots, with grain and starve specks); `K.levels(P, ink, draw, covs)` -> an array of canvases, `null` until each job
  runs, with `.jobs` (one per coverage; return them from prep) and `.at(i)` (prints level i now if missing);
  `draw(g, cov, i)` lays the tone for coverage `cov`.
- **Motion:** `K.ease.out / inOut / back / elastic / bounce` (each takes 0..1, clamped), `K.clamp`, `K.lerp`,
  `K.smooth(e0, e1, x)`, `K.fade(E, e)`, `K.rand(seed)` (mulberry32: returns a function).
- **Type:** `K.font(weight, px, "disp" | "mono")` -> a font string in the theme's faces;
  `K.text(g, str, x, y, { ink, cov, align, spacing, font, base })` (with `ink` it prints in that ink's dots in the
  blend; without, it lays tone for `K.screen`).
- **The card:** `K.g` (the effects canvas, card CSS px), `K.card`, `K.run` (the head's record), `K.w`, `K.h`, `K.top`,
  `K.box`, `K.st`, `K.ready`.
- **Hits:** `K.ring({ x, y, r0, r1, w0, ink, cov, dur, delay })` (an expanding halftone ring; defaults 6, 80, 6,
  "loss", 0.9, 0.4 s, 0); `K.spark({ x, y, n (at most 80), ink (a name, or function (rnd) -> a name), sp: [min, max],
  r: [min, max], life: [base, extra], grav, seed | rnd, streak })` (a spray of ink drops; streak: they smear along
  their flight); `K.shake(dur, amp)` (the card jolts, then sags; amp at most 16); `K.flash(strength)` (the red flash
  over the whole card: only inside a heavy loss's `hit`, never stronger than 0.72 (the first loss's), never closer
  than 0.77 s to the last one; returns whether it fired); `K.jolt(el, frames, opts)` (a Web Animation on the card or
  anything inside the reel; ?risoslow applies); `K.hitClassic(E)`; `K.caption(E, e, x, y)` (the classic caption,
  anywhere).
- `K.d` (device px per CSS px, 1 to 2), `K.TH` (the theme), `K.reduced` (prefers-reduced-motion).
- Outside a reel (`T82RISO.strip`, and `T82RISO.kit(root, g)` for a lab or the FX layer) the kit is the shared half:
  the inks, print, motion and type, with `K.pat` pinned to the `g` given by default; no `K.g`, `K.card`, hits or box.

**The scene's kit (tone only: the engine screens and inks every layer):** `K.d` (device px per CSS px; the poster
1.6), `K.k` (device px per scene unit: snap small shapes with it), `K.TH`, `K.rgb(ink)` (`light` resolved; null for
an unknown ink), `K.tone(a)`, `K.rand(seed)`, `K.noise1D(seed)`, `K.fbm(n, x, oct)`, `K.lerp`, `K.clamp`,
`K.smooth(a, b, x)`, `K.ease(t)` (in-out), `K.vgrad(g, y0, y1, [[stop, tone], ...])`, `K.circle(g, x, y, r)` and
`K.ellipse(g, x, y, rx, ry)` (each begins the path), `K.knock(g, fn)` (draw fn as a knockout), `K.knockRadial(g, x,
y, r, a)`, `K.spacedText(g, text, x, y, spacing, align)`, `K.seams(g, x, y, r, rot)` (basketball seams),
`K.font(weight, px, "disp" | "mono")` (--t-disp or --t-mono, as in the reel), `K.trace(g, fn, x0, x1,
step)` (lineTo along y = fn(x), the first point too). No `K.pat`, `K.blend` or `K.reduced`: the engine owns ink and
motion.

## The QA hooks (both engines; the harness and the lab use them, the game never does)

- `T82RISO.create(ov, season, opts)`: `opts.root` (the element whose theme to print in), `opts.loss`, `opts.dots`,
  `opts.onUse` (above), `opts.clock` (a function returning seconds; replaces performance.now; ?risoslow still divides
  it), `opts.manual` (no requestAnimationFrame loop and no idle scheduling; the gate opens at once, so load the faces
  first). Returns `{ openMonth, stamp, closeMonth, finale, destroy, qa }`, plus `frame()` (one frame at the clock's
  time) when manual. `qa.runJob()` runs ONE pending prep step (a face warm-up, or one job) and returns true, or false
  when nothing is pending; `qa.state()` -> `{ prepped (ids), canvasBytes (classic's plus every live variant's),
  pending (steps, warm-ups included), window, playing, next, dots, off (["kind:id"]), ready }`.
- `T82RISO.strip({ root, games, streaks, gi0, cl0, mi, cssW, d, dots })` -> one settled month strip (the Reprint Lab
  and the harness's match check). `T82RISO.kit(root, g)`, `T82RISO.inks`, `T82RISO.version` ("v67").
- `T82PRINT.mount(host, spec, { defer, root, clock, manual })` -> `{ play, update, rebuild, destroy, scene, frame? }`
  (`scene`: the id that actually printed; in manual mode `frame()` draws the reveal at `clock()` and returns true while
  it is still running). `T82PRINT.print(spec, { root, width, dpr })` -> `{ print, names, filter, scene }`.
  `T82PRINT.scenes()` -> `["lake", ...]` (the indexed scenes that are registered). `T82PRINT.version` ("v67").

## The laws (test.js and tools/style-law.js enforce what they can)

1. **Colors:** only through the kit's inks. No hex, rgb(), hsl() or named colors in an art file (the style law also
   flags a bare quoted color name like "white"; the kit's ink names are allowed); black only as a coverage mask
   (`K.tone`, or "#000" / rgba(0,0,0,a) as the mask). **Fonts:** only the theme's faces through the kit.
2. **Copy:** zero em-dashes in an art file's strings. Captions in the reel's voice (short, uppercase mono, the city
   and date from E).
3. **Photosensitivity:** only `K.flash` lights the whole card, and the engine limits it. Nothing covering more than a
   tenth of the card may swing between bright and dark more than three times a second.
4. **Deterministic:** randomness only from `K.rand(seed)` with E.seed, D.seed or D.gi, so a replay prints the same.
   No Math.random, no Date.
5. **ES5, like the engines:** an IIFE, `"use strict"`, `var` and `function`; no modules, classes, let/const, arrow
   functions or template strings.
6. **Budgets.** tools/art-qa.mjs measures them in Chromium on the owner's M1 with the CPU throttled 4x (a stand-in
   well below an iPhone SE), 375x812 at 2x; every ratio is to the built-in measured the same way in the same run
   (the built-in is timed before and after the variants and pooled). A frame's ms is the whole frame (`frame()` plus
   finishing its pixels). KB = 1024 bytes, MB = 1024 KB.
   - **A loss moment:** a frame (ledger + veil + hero + caption + particles, the whole frame) no slower than 1.5x
     classic's on average and 2x at the 95th percentile; each prep job at most 25 ms (its median over every reel that
     ran it); all jobs together at most 1.5x classic's total; at most 12 MB of canvases in `K.st` at its peak (aim for
     half: the window can hold three variants at once). Classic's eighteen levels (17.3 MB) are the exception: they are
     the reference and are kept for the whole reel. The harness also reports "the moment alone" (the frame less a
     moment that draws nothing) for information.
   - **A dot set:** a moving strip frame (only frames inside a stamp's live window) at most 1.5x classic's; the
     settled season (seven `strip()` reprints) at most 1.5x.
   - **A scene:** the banner's bake at most 1.25x lake's, with lake baked in the scene's first light; the reveal's
     frames at most 1.25x.
   - **File size:** loss at most 10 KB, dots 6 KB, scene 16 KB (unminified source; test.js checks it).
   - **The baselines** (`node tools/art-qa.mjs all`, 2026-09-30, 2 reps; absolute ms move about 20% between runs on a
     shared machine, so only same-run ratios are judged):

     | built-in | at 4x throttle on the M1 |
     |---|---|
     | classic loss | frame 13.2 ms avg, 20.3 ms p95 (the moment alone 11.6 ms over a 1.6 ms floor); prep 19 jobs, the longest 5.3 ms, 76.3 ms in all; canvases 17.3 MB; the stamp 1.4 ms |
     | classic dots | moving strip frame 3.2 ms avg, 6.5 ms p95; the settled season 29.0 ms |
     | lake | banner bake 151 ms (golden, the mean of 82-0, 64-18, 41-41, 20-62); mount 157 ms; reveal frame 27.1 ms avg, 44.6 ms p95 |

     So a loss variant's frame may average up to about 20 ms and each prep job 25 ms, a dot set's moving frame about
     4.8 ms, a scene's bake about 190 ms (the poster bakes one layer per task, so the page never locks up).
   - **Also checked:** it played (onUse named it, the engine had it playing, it was not turned off); no console errors
     and no engine warnings; a dot set's live ledger equals its `strip()` reprint; WebKit (`--webkit`): no errors, and
     it printed itself.
7. **Distinct:** a new variant differs from every other one of its kind in at least two of: material or letterform,
   entrance, aftermath or exit, composition. The lab's "10 in a row" is the test.
