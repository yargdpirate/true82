WHAT IT DOES
Tap a community label chip on a results player card and a one-line strip
opens under the chip row: agree arm, the label, disagree arm. The vote
posts to the same /api/traits op=vote the poll page uses, the strip
reports the tally in place, and the question retires from the widget and
/bonuses/ so nobody gets asked twice.

WORKER CHANGE (functions/api/traits.js, additive only)
- op=labels now returns each hit's question id (q.id). Two SELECTs gained
  one column each; the hit objects gained `id`. Older clients ignore it.
- SOURCES gained "card" so votes attribute correctly instead of
  degrading to "direct". Everything else in the worker is untouched.

RULINGS BAKED IN
- Results roster only. Draft-pool and Caveman chips keep the old
  in-place expansion, untouched.
- Engine chips (3PT, GRAVITY) ARE votable as of v49.7 (owner ruling).
  They carry no consensus row of their own, so op=labels now returns a
  `qids` map of every ACTIVE question per player-season and the client
  stamps the engine chip with the community question that asks the same
  thing: 3PT -> Three-Point Shooter, GRAVITY -> Super Three-Point Shooter.
  The strip keeps the ENGINE's wording (3PT opens as FLOOR SPACER) while
  the vote pools with /bonuses/. Where no such question exists yet for
  that player-season the chip simply stays expand-only, so coverage grows
  as op=roster creates rows. The legend note was rewritten to match.
- The chip stays an abbreviation when its strip is open, so the chip row
  never reflows. The strip carries the full label.
- ONE LINE IS A HARD CONSTRAINT. Arms are a fixed track, the label is the
  only elastic one, and TRAIT_STRIP_LABEL shortens the five labels that
  cannot fit beside two arms in a 320px card. Harness h9 measures all 20
  labels at 320/360/375/390/430 and fails on a second line or an ellipsis.
- Votes queue 1300ms apart because the worker's cadence fence is 1200ms,
  and a rate_limited reply retries once. A brigade never sees an error.
- Network failure fails quiet ("VOTE COUNTED"): the tap still reads real.

QA on deploy
- Finish a classic run, scroll to the roster, tap a gold or red chip:
  strip opens on one line, arrows are thumb-sized, label is centered.
- Vote: arrow lights instantly, text becomes "78% SAY YES" or "3 YES . 1 NO".
- Tap chips on several cards quickly: every vote lands, none error.
- Open /bonuses/ afterwards: the question you just voted should not reappear.
- Narrow to an SE (375) and an SE 1st gen (320) in device emulation and
  confirm no wrap on the longest labels (Curry's SUPER SHOOTER).

ANALYTICS (v49.6 pass - what lands in /avocado)
Every event carries surface "card", source "card", the question id in
challenge, and a per-page sid.
- traits_question action "view": a strip opened. One per open, including
  reopens.
- traits_question action "dismiss": a strip closed UNVOTED; value = dwell
  ms. A strip closed with a vote in flight never dismisses.
- traits_vote action yes/no: a counted vote; outcome = consensus status,
  value = API latency ms, ordinal = how many card votes this page view
  (brigade depth: max ordinal per sid is how deep they went).
- traits_vote_error: a vote the player believes landed but did not;
  outcome = rate_limited / bad_reply / network, same ordinal. The name is
  whitelisted in functions/api/event.js (that file MUST deploy with this
  package or error events are silently dropped by ingestion).
Funnel reads: view -> vote conversion per question; decide time =
vote.ts - view.ts joined on sid + challenge; hesitation = dismiss value.

v49.7 ARROW PROMINENCE
The strip is now a recessed field and the arms are raised keys on it:
gradient face, lit top edge, hard bottom lip, and a real 2px drop on
press. Glyphs went 15->18px and brightened. Voting fills the arm solid
(amber for agree, ember for disagree) instead of tinting it. Arms are
44x44 at 375+ and 40 wide at 320-374. One cue per DEVICE the first time
any strip opens: the arms bounce once so a new player learns they are
buttons, keyed on t82_trait_vote_cue_v1 and never repeated. Hover states
are desktop only; prefers-reduced-motion kills the cue.
